# 日志与业务库查询

项目：rag-databrain  
更新：2026-10-24

模型只填固定表单。CLS 查询语句和 SQL 由服务端拼。大公司用腾讯云 CLS，小公司用自己的库，工具名和参数相同，用环境变量切换。

## 需求理解

要做：

- 两个工具。`search_logs(window, service, level, keyword)` 查日志。`lookup_row(view, key)` 按主键查一条业务记录。
- `window` 只允许 `15m`、`1h`、`6h`、`24h`、`7d`。服务端换成起止时间。
- `level` 只允许空、`ERROR`、`WARN`、`INFO`。`service`、`keyword`、`key` 限长，`service` 只允许字母、数字、`-`、`_`。
- `view` 的枚举来自配置，不在列表里的表不能查。
- 默认 20 条，上限 50。超时、失败、未配置都回一条短的工具结果，循环继续。空结果不当证据。
- 有记录时给 `sources` 加来源标签，最后一轮才肯把模型正文发出去。进模型的正文按 `MAX_CONTEXT_CHARS` 截断，并写明「共 N 条，已截断」。
- `LOG_BACKEND=sql` 打参数化查询；`LOG_BACKEND=cls` 调 CLS `SearchLog`。`DATA_BACKEND=sql` 时 `lookup_row` 打允许的视图；未设置则回「业务库未配置」。
- 只读账号。密钥、TopicId、表名只在环境变量里。

不做：

- 不让模型提交 SQL 或 CLS 查询语句。
- 不写库、不删日志、不开 CLS 导出。
- 不把日志或业务行写入 `documents` / `chunks`。
- 不上进程沙箱。这两个工具只读 HTTP 或 SQL，不执行命令。
- 不改消歧。pin 只覆盖 `retrieve` 的 query，不套到这两个工具。
- 现在只有 `/ask` 和 `/ask/stream`。工具只挂在这条内部循环上。以后若有公开入口，工具列表不要带上它们。
- 不做 Loki、Elasticsearch，也不做登录审计。

复用：

- `stream_ask` 的工具循环、未知工具仍回一条结果、最后一轮禁止工具、相同参数不重复打。
- `MAX_CONTEXT_CHARS`、`MAX_AGENT_STEPS`。
- 知识库存储仍只经过 `store.py` / `storage.py`。日志和业务库用各自的连接，不进切片缓存。

## 步骤

| ID | 做什么 | 主要文件 |
|---|---|---|
| 1 | 放行两个工具。参数在服务端校验。未配置时回固定短句。有记录才写入 `sources`，空结果和失败不计入证据。工具异常留在工具结果里，不变成 SSE `error`。 | `src/rag_databrain/live.py`、`src/rag_databrain/graph.py` |
| 2 | `LOG_BACKEND=sql` 与 `DATA_BACKEND=sql` 走参数化查询。视图名单来自配置。 | `src/rag_databrain/live.py`、`.env.example` |
| 3 | `LOG_BACKEND=cls` 把同一张表单编成 `SearchLog`。`lookup_row` 仍走步骤 2。 | `src/rag_databrain/live.py`、`.env.example` |

## Step 1 commit

```text
feat: 放行日志和业务查询工具，未配置时回固定结果，避免模型编造记录。
```

做完时：模型调用 `search_logs` 或 `lookup_row` 得到「日志源未配置」或「业务库未配置」，回答是不知道，而不是「未知工具。」。相同参数第二次不再执行。系统提示说明线上日志用 `search_logs`，业务记录用 `lookup_row`，制度和文档仍用 `retrieve`。

`sources` 今天只在 `retrieve` 有切片时才有值，最后一轮没有 `sources` 会直接回「知识库为空」。这一步起，工具带回记录才追加来源标签；没带回就不追加。

## Step 2 commit

```text
feat: 用参数化 SQL 查日志表和允许的业务视图。
```

做完时：配好 `LOG_DATABASE_URL` 和固定日志表后，`search_logs` 只按窗口、服务、级别、关键字过滤。配好 `DATA_VIEWS` 后，`lookup_row` 只能查名单里的视图和对应主键。来源标签形如 `sql:app_log`、`view:orders`。连接失败回「查询失败」，不把驱动异常原文塞进上下文。

## Step 3 commit

```text
feat: 日志改走腾讯云 CLS 检索，查询语句仍由服务端拼。
```

做完时：`LOG_BACKEND=cls` 使用 `CLS_REGION`、`CLS_TOPIC_ID`、`CLS_SECRET_ID`、`CLS_SECRET_KEY` 调 `SearchLog`。关键字作为词项写入，不把模型的字符串原样当成查询语句。来源标签形如 `cls:订单主题`。签名用标准库，先不加腾讯云 SDK。`lookup_row` 仍只走 SQL。

合并示例：合并 2 和 3。说「继续」或「做 step N」开始写。
