# Agent 开发名词

活文档。只收这条知识库 Agent 里会碰到的词。选型见 [architecture.md](architecture.md)，面试题见 [选型面试题.md](选型面试题.md)，评测见 [评测.md](评测.md)。

## 一句话

离线把文档变成可检索的切片。在线先把问题改清楚，再检索、精排、装进窗口、生成。准不准分成几个数：正确切片进没进前 K、排得靠不靠前、交给模型的几条盖住了多少事实、答案对不对。引用校验是生成之后的事：逐句看答案能不能被本轮切片撑住。

## 请求怎么走

**Agent。** 模型自己决定下一步：调用工具，或者直接作答。固定写死「检索一次再生成」就只是一条流水线。

**工具调用。** 把检索描述成一个函数交给模型。模型返回函数名和参数，程序执行，把结果塞回对话，模型再决定继续搜还是作答。本仓库只有检索这一个工具。

**loop。** 模型外面的驱动：想、调工具、看结果、再想，直到写出答案。模型只提议下一步。还要不要再来一轮、这一轮准不准调工具，由 loop 决定。必须有步数上限，否则它会一直搜。本仓库最后一轮禁止再调工具，强迫它作答或停住。相同问句不搜第二次。

**沙箱。** 一次工具调用允许碰到的范围。编码代理里，命令和文件要限制在同一处，换后端时一起换，不确定的命令先等人点头。本仓库没有命令可跑：只放行检索，检索只读切片。不认识的工具返回一条结果，不能起进程或改库。会执行命令的工具出现之前，不上进程沙箱。

**步数上限。** loop 最多走几轮。上限太小，资料不够也得答；太大，同义问句会被反复检索。相同问句再出现时，本仓库直接让它用已有资料作答。

**工作记忆。** 多轮里的「它」「再详细点」要靠最近对话才能接上。对话和知识库资料抢同一个窗口，所以只留最近几轮，并给对话设预算。本仓库由请求带上历史，最多占窗口三成，不写入知识库。

**会话隔离。** 多人同时提问时，一个人的对话只能出现在他自己的提示词里。服务端不保存会话：历史跟着这次请求进来，一进函数就复制成一份新的，请求结束就丢。知识库切片所有请求一起用。对话只留在各自的请求里。进程内放一张会话表，多个 worker 各记各的，键用错了还会串到别人的回答里。本仓库的图不挂检查点，避免所有请求写进同一条记忆。

**消歧。** 一种读法能补成唯一问句，就改写后去检索。几种读法会搜到不同文档，这一轮只反问一个缺口，先不检索。本仓库在进 loop 之前做这一次判断。

**查询改写。** 把带指代、带省略的问句写成不看历史也能检索的一句。生成仍用用户原话。改写解决的是「没说全」，解决不了「两套都说得通」。

**SSE。** 一次提问之后，服务端把 token 连续推下来，结束就断开。本仓库流式走 `POST /ask/stream`。普通问答仍是一次返回完整 JSON。

## 文档怎么进库

**解析。** 从文件里重建阅读顺序：标题、段落、表格、图片。字都在、表被拆平，后面的检索救不回来。本仓库先拆块，再切分。

**Chunk（切片）。** 一块能单独被检索、也能单独放进窗口的文本。太大装不进窗口，太小丢掉章节。本仓库块首写标题路径和页码；表格保留行列。

**Embedding（向量）。** 把一段文字变成一串数。语义接近的文字，向量也接近。型号只差一个字母、错误码只差一位时，向量常常仍然很近。

**索引。** 为了大量切片时不用逐条比较。向量索引按近似最近邻查找，全文索引按关键词查找。本仓库把向量存在 PostgreSQL 的 JSONB 列里，查询时全表算余弦，关键词在内存里算，还没有单独的索引服务。

## 问题怎么找到证据

**检索。** 从切片里找出可能有用的候选。本仓库是关键词和向量各召回一批，再合成。

**BM25。** 关键词打分。问句里的词在某切片里出现、又不太常见，分就高。错误码、型号这种必须原样出现的词，靠它比靠向量稳。一条切片的分数是问句里每个词的贡献相加。词 `t` 的贡献：

`IDF(t) = ln( (N − n_t + 0.5) / (n_t + 0.5) + 1 )`

`贡献(t) = IDF(t) × (tf × (k1 + 1)) / (tf + k1 × (1 − b + b × dl / avgdl))`

`N` 是参与打分的切片数，`n_t` 是含有 `t` 的切片数，`tf` 是 `t` 在这条切片里出现的次数，`dl` 是这条切片的词数，`avgdl` 是这些切片的平均词数。`k1 = 1.5`，`b = 0.75`。对数是自然对数。中文按连续两字切，英文和错误码整词。只留下分数大于 0 的切片。

**向量检索。** 用问句的向量找近邻切片。用词对不上、意思接近时能召回。近邻可以是另一型号、另一个错误码。相似度是余弦，越接近 1 越像：

`cos(q, d) = (q · d) / (|q| × |d|)`

分子是对应维度相乘再相加。分母是两个向量各自的长度。长度是 0 时记 0。本仓库对过滤后的切片全表算，取最高的一批。

**RRF。** 把两路各自的名次合成一个分数，再按这个分数排序。BM25 分和余弦分量纲不同，直接相加没有意义。某一路特别靠前的切片，合成后仍靠前。名次从 1 起，只在某一路出现的切片只加那一路：

`RRF(d) = Σ 1 / (60 + rank_i(d))`

两路都排第 1 时，`RRF = 1/61 + 1/61`。一路第 1、另一路没有时，`RRF = 1/61`。

**Rerank（精排）。** 召回只求「可能相关」，精排再读完整问句和整段文字，把真正能用来回答的证据往前排。分数只比较这一批候选，不是答对的概率。本仓库要另装依赖并写上模型名才会跑；不配就停在 RRF 的名次。

**硬约束。** 型号、版本、错误码先按原文过滤，再交给排序模型。这些字段差一位，向量和精排都可能看不出来。本仓库会先收窄；问句同时提到两个错误码、滤完没有切片时，退回原集合。

**上下文组装。** 按相关度从高到低把切片装进窗口，装到预算为止。检索到 30 条不代表 30 条都给模型。本仓库还有对话占用的预算，超了就丢掉后面的切片。

## 答案怎么被拦住

**幻觉。** 答案写得很顺，依据却不是知识库。模型没调检索就用训练知识作答，或者检索到了切片仍补上一句库里没有的规定、数字、日期，都算。

**无证据不输出。** 这一轮没有任何检索切片，就不把模型正文发给用户，只回复不知道。它看的是「有没有切片」，不看切片里的句子能不能推出答案里的每一句。本仓库做的是这一层。反问用户把问题说清楚，不算回答，可以不检索。

**引用校验。** 生成之后，把答案拆成句子，逐句核对这句能不能从本轮检索到的切片里得到。对得上的留下，对不上的删掉或标成没有依据。它要拦住的是另一种情况：切片确实检索到了，模型仍夹了一句自己的知识。

常见做法有三档，越往下越严，也越贵：

| 做法 | 在核对什么 |
|---|---|
| 答案里标出来源编号，检查编号对应的切片是否被引用 | 格式上有没有指向某条切片 |
| 专名、数字、日期必须在切片原文里出现 | 这些token有没有被模型换掉 |
| 用另一个模型判断切片能否推出这句话 | 意思上站不站得住，改写过的句子也能查 |

只做第一档，模型可以标一个相关切片，句子本身仍然是编的。第三档要多一次模型调用，换了说法的句子容易被误判成无依据。本仓库没有这三档。返回的来源只是文档名，用来告诉用户材料从哪份文件来，不是逐句核对。

**证据充分性。** 精排可以把最相关的几条排到前面，这几条合在一起仍可能答不全。充分性问的是「这些证据够不够回答」，发生在生成之前或生成之后都可以。引用校验问的是「已经写出的这句有没有依据」。两件都没做的时候，模型会用半份证据写出完整步骤。

## 准不准怎么算

每个数只解释一个阶段。先有标注：哪些切片是正确证据，回答必须覆盖哪些事实，怎样算答对。多题先按题算，再取平均。`K` 是截断条数，`Rel` 是这道题的正确切片。召回的 `K`、精排前的 `K`、交给模型的 `K` 不是同一个数，写指标时必须带上。本仓库还没有标注集，下面这些数现在算不出来。评测怎么摆组见 [评测.md](评测.md)。

下面用同一道题当底：正确切片 4 条，前 5 条里命中 2 条，第一条正确切片排在第 2 名。

**Top-K。** 只留分数最高的 K 条。本仓库关键词和向量各取一批，融合后再截一批去精排，最后留下更少的几条装进窗口。

**召回率（Recall@K）。** 该找到的正确切片，前 K 条里找到了多少。

`Recall@K = |前 K 条 ∩ Rel| / |Rel|`

上例 `Recall@5 = 2/4 = 0.5`。分母是这道题标出的正确切片，不是库里的全部切片。评测用 `Recall@20` 看精排之前的候选。这里是 0，后面的精排没有机会。

**精确率（Precision@K）。** 前 K 条里，有多少是正确切片。

`Precision@K = |前 K 条 ∩ Rel| / K`

上例 `Precision@5 = 2/5 = 0.4`。召回看漏没漏，精确看前 K 条掺了多少无关切片。精确低时，窗口会被无关切片占满。

**F1@K。** 精确率和召回率的调和平均。两边差很多时，它更靠近较小的那个，不会被高的一边拉上去。

`F1@K = 2 × Precision@K × Recall@K / (Precision@K + Recall@K)`

上例 `F1@5 = 2 × 0.4 × 0.5 / 0.9 = 4/9`。

**命中率（Hit@K）。** 前 K 条里只要有一条正确切片就是 1，否则是 0。多题取平均，就是至少碰到一条的题比例。它不看碰到了几条，也不看排第几。上例 `Hit@5 = 1`，尽管四条正确切片只回来两条。

**MRR@K。** 第一条正确切片排第几。出现在第 1 名，这一题得 1；第 2 名得 1/2；第 `r` 名得 `1/r`。名次大于 K，或前 K 里没有正确切片，这一题得 0。再对题平均：

`MRR@K = (1 / 题数) × Σ (1 / rank)`

上例这一题贡献 `1/2`。评测用 `MRR@5`。它只看第一条，第二条正确切片排在哪不算。

**nDCG@K。** 正确切片越靠前，分越高。相关记 1，不相关记 0。先把前 K 名折成 DCG，再除以理想排序的 IDCG，所以满分是 1。名次 `i` 的折扣是 `log2(i + 1)`，第 1 名折扣是 1，越往后越小：

`DCG@K = Σ rel_i / log2(i + 1)`，`i` 从 1 到 K

`nDCG@K = DCG@K / IDCG@K`

IDCG 是把这道题的相关切片尽量排到最前时的 DCG。前 K 名里第 1 名相关、第 3 名相关时，`DCG@5 = 1/log2(2) + 1/log2(4) = 1.5`。两条都排到最前时，`IDCG = 1/log2(2) + 1/log2(3) ≈ 1.631`，`nDCG@5 ≈ 1.5 / 1.631 ≈ 0.92`。排到第 K 名以后，这一次的前 K 里就没有它。评测用 `nDCG@5`。相关只有 0 和 1 时，增益就是 `rel_i` 本身，不必再写成 `2^rel − 1`。

**MAP。** 每道题在「命中正确切片的那些名次」上把当时的精确率平均，再对题平均。`rel_k` 是第 k 名是否正确，是则为 1：

`AP = (1 / |Rel|) × Σ Precision@k × rel_k`

`MAP = (1 / 题数) × Σ AP`

它把找得全不全和排得靠不靠前揉成一个数。评测不报它，这两件事用 `Recall@20`、`nDCG@5`、`MRR@5` 分开看。

**证据召回（Evidence Recall@K）。** 必须覆盖的事实里，前 K 条盖住了多少。分母是事实条数，不是切片数。一条切片可以盖住多件事实，一件事实只算一次。

`Evidence Recall@K = |前 K 条盖住的事实| / |必须覆盖的事实|`

必须覆盖 3 件、前 6 条盖住 2 件时，`Evidence Recall@6 = 2/3`。评测用 `@6`，因为最终交给模型的是这几条。`Recall@K` 高而这个数低：正确切片进来了，合在一起仍答不全，或同一文档的相邻切片占满了名额。

**答案正确率。** 答对的题数除以题数。

`答案正确率 = 答对的题数 / 题数`

证据齐了仍可能写错。这个数下降时，先看 Evidence Recall：低就是没给到证据，高就是给到了仍写错。

**P95。** 把同一批请求的耗时从小到大排，取第 `⌈0.95 × N⌉` 次。100 次就是第 95 次，也就是比 95% 的请求都慢的那一次。20 次是第 19 次。平均数会被少数很快的请求拉低。精排增加的时间和生成的时间分开记。

## 放在一起看

一次企业问答里，这几个词各管一刀：

检索决定候选里有没有那条证据，用 `Recall@K` 量。Rerank 决定它排不排得进窗口，用 `nDCG@K` 和 `MRR@K` 量。上下文组装决定窗口装得下几条。`Evidence Recall@K` 看这几条合在一起盖住多少事实。无证据不输出决定「一条都没有」时发不发模型正文。答案正确率看写对没有。引用校验决定「有切片」时，正文里每一句是否都站得住。

`Recall` 高、`nDCG` 低：证据进了候选，没有排上来。`nDCG` 高、Evidence Recall 低：最像的几条在前面，事实仍不齐。Evidence Recall 高、答案正确率低：问题在生成，证据已经给到了。
