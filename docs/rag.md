# RAG

活文档。切分、名词、评测收在这里。选型决定仍在 [architecture.md](architecture.md)。面试怎么讲见 [选型面试题.md](选型面试题.md)，别家做法见 [面试经典实践.md](面试经典实践.md)。日志和业务库不在本文，见 [日志与库查询.md](日志与库查询.md)。

## 一句话

离线把文档洗干净、切成块、嵌成向量，写入 PostgreSQL。在线先把问题改清楚，再检索、精排、按预算装进窗口、生成。这一轮没有检索到切片，不把模型正文发给用户。

`POST /ingest` 只收 `.txt`、`.md`、`.pdf`。先拆成段落、表格、图片、脚注、代码，再按种类切。同名再传：内容哈希相同则跳过，否则只嵌新切片并整份换掉旧版。检索把切片拉回内存，型号和错误码先收窄，BM25 与余弦各取一批，RRF 融合；配了精排模型才做交叉编码。同一来源有封顶。`POST /ask` 和 `POST /ask/stream` 走同一套 loop。

## 表格清洗

表格在切分之前洗。洗完每一行自己能读懂，不依赖左边的格子或上一行。本仓库现在只做了其中两步：合并格向下再向右补，多级表头竖着拼成「部门 / 销售」。Excel 拆 sheet、一行一条目还没有。入库格式仍是 Markdown 表，表太长按行切开并重复表头。

三步按这个顺序做，不能颠倒。先拆 sheet，再填合并格，最后才行转条目。先转条目，合并格还是空的，城市、部门这种分组键会丢。

### 拆 sheet

一个工作簿里每个 sheet 是一张独立的表。sheet 名写进块首路径，例如 `[报销标准.xlsx / 住宿]`。空 sheet、隐藏 sheet 丢掉。列名碰巧相同也不要把两个 sheet 拼成一张表。交通和住宿不是同一张表。

PDF 的跨页是另一回事。下一页列数相同、没有新表题、第一行是重复表头或仍是数据，才拼回上一张表。拼的时候去掉重复的那一行表头。这是页的续写，不是 sheet。

本仓库不读 `.xlsx`。PDF 跨页用 `tables_continue` / `merge_tables`。接表格文件时按 sheet 拆开，再走进下面两步。

### 填合并格

Excel 的合并格只在左上角存字，其余格子是空的。PDF 抽出来也常常是空单元格。不补的话，第二行只有「员工 / 500」，检索和生成都不知道这是北京。

补的顺序是先向下、再向右：

| 城市 | 职级 | 上限 |
|---|---|---|
| 北京 | 经理 | 800 |
|  | 员工 | 500 |

向下补完，第二行的城市变成「北京」。向右补的是表头横跨多列的情况，例如「上限」盖住「国内」「国外」。先向右再向下，会把左边的列表头抄进不该抄的空列。

多级表头在补全之前先认出来。连续最多三行、比下面的数据更疏、看起来像表头，就当作表头。补全之后同一列从上到下拼，去掉重复，得到「部门 / 销售」。数据区再补一次合并格。

本仓库 `fill_merged` 就是先下后右。它分不清「合并出来的空」和「这格本来就没有值」。真空会被左边或上边的字填上。要消掉这个误伤，得读合并区域本身（xlsx 的 merge range，或 PDF 单元格框），只填区域内部。现在没有合并区域，所以真空也会被填。

### 行转条目

补全并拼好列名之后，每一行数据写成一条自洽的文本，而不是一整张 Markdown 的一个向量。问「北京员工住宿上限」时，向量要落在这一行上，不要被表头和相邻城市冲淡。

上一张表洗完是三条，路径里带 sheet 或标题：

```text
[报销标准.xlsx / 住宿] 表格：住宿，列：城市、职级、上限，共 2 行。
[报销标准.xlsx / 住宿] 城市：北京；职级：经理；上限：800
[报销标准.xlsx / 住宿] 城市：北京；职级：员工；上限：500
```

第一行是表级摘要，用来把人带到这张表。后面每行是一个条目。全空的行丢掉。和表头完全相同的行丢掉。单元格里的 `|` 和换行改成空格，避免再被看成一张新表。

数字留在条目里给模型抄。加减乘除不要让模型口算，要汇总再另做工具。本仓库还没有行转条目。现在是摘要加整张 Markdown；超过大约 1000 字或去掉表头后多于两行数据时，按行切开，每块重复表头和摘要。摘要在 `table_summary`，切表在 `_chunk_table`。

## 五种切法

一种文档只用一种主切法。超长的那一块才允许再落回固定长度。不要先把整份滑窗，再指望检索把表格拼回来。

| 切法 | 在哪一刀断开 | 适合 | 本仓库 |
|---|---|---|---|
| 固定长度 | 数满 N 个字符或 token 就切，相邻块重叠一段 | 没有标题的长文 | 只用在超过 500 字的正文上。500 字一块，重叠 80 字 |
| 递归分隔符 | 先按空行，再按句号，最后才按长度 | 结构弱的杂文 | 不用。`.txt` 只按空行拆成段，段超长才滑窗 |
| 文档结构 | 标题、表格、代码、列表各自成块，块首写下级路径 | 制度、Markdown、有标题的 PDF | 主路径。`parse_document` 出块，`chunk_blocks` 按种类切 |
| 语义 | 相邻句各自嵌入，余弦掉下去就断开 | 标题对不上、话题在段内切换的长文 | 不做。入库要多算一批向量，断点也不稳定 |
| 父子块 | 小块拿去嵌入和检索，命中后把所在的节交给模型 | 小块能搜到，生成时缺前后文 | 不做。检索和生成用同一块，块首已经写了标题路径和页码 |

### 固定长度

适合几乎没有标题、段落也分不出来的长文，比如爬来的纯文本、OCR 之后挤成一整段的扫描件。它只数满 N 个字就切一刀，句子、表格、代码都会被切断。后半段没有列名或上一句，检索能命中，生成对不上。所以它只适合不断开也没有结构可保的正文，不适合制度、表格和代码。本仓库只把它用在已经按结构切开、仍超过 500 字的那一段正文上。

### 递归分隔符

适合有段落、有句号，但没有稳定标题的杂文、邮件、纪要。先按空行拆，一段仍然超长再按句号拆，最后才按字数切。它比固定长度少把一句话切成两半。Markdown 表格和代码仍会从管道符、缩进中间断开，因为这些分隔符它不认识。本仓库的 `.txt` 只做到第一步：按空行拆段，段超长才滑窗。

### 文档结构

适合标题、表格、列表、代码各自成块的材料：制度 Markdown、带章节的 PDF、说明书。先按种类切开，块首写下「差旅 / 住宿限额」这种路径，超长的那一节再滑窗。问「年假怎么批」时，向量对得上这一节，而不是对上从第三节中间切下来的半句。表和代码不进滑窗。这是本仓库的主路径。`parse_document` 出块，`chunk_blocks` 按种类切。图片、脚注、代码整段一块。表走上一节的清洗。

### 语义切分

适合同一段里话题会换、标题又对不上问法的长文，比如一篇里先讲报销再讲考勤，中间没有标题。相邻句各自做向量，相似度掉下去就断开。代价是入库时要多算一批向量。换一个嵌入模型，断点就变，内容哈希对不上，整份文档得重嵌。本仓库不做。

### 父子块

适合小块才能搜准、生成时却必须看到整节的材料。例如「第三步」四个字能被检索命中，作答却要这一节的前后文。小块去嵌入，命中后再把所在的节交给模型，多存一份父文本。本仓库检索和生成用同一块，靠块首的标题路径和页码补上「这是哪一节」。表太长时每块重复表头，没有另存一份父块。

## 重叠长度

重叠只属于固定长度那一刀。它让正好切在窗口边上的那句话两边都还在。表、代码、图片、脚注不加重叠。表按行切开时重复的是表头，那是结构，不是滑窗。

设两个数：块长 `size`，重叠 `overlap`。下一块从 `size - overlap` 之后开始。重叠必须小于块长，相等或更大就会停在原地。本仓库是 500 和 80，步进 420。80 / 500 = 16%。

重叠取「可能被切在边界上的那条事实」的长度，不取一个固定比例再到处套。

- 制度、说明文，一条规则大约一两句，几十个字到八十个字。80 字盖住被切开的那句。这是现在的设置。
- 事实更长，例如一段必须整段才成立的操作步骤，先把这段收成结构块，不要把重叠加到 200 去硬保。重叠盖不住一整节。
- 起步可以用块长的 10% 到 20%。短于大约 40 字，中文半句话仍会只落在一边。长过大约 20%，同一句话会占满检索的前几名。

只在两种情况下改数字。评测里答错的那句正好跨在两块边界上、两边都没进前 K，把重叠加长到能盖住那一句。前 K 里经常是同一段的两个窗口，上下文被同一句话占两次，把重叠缩短，或命中后把相邻窗口合成一条证据。本仓库还没有做第二种，重叠块会同时入库。

按字符，不按 token。中英混排时，同样的字符数对应的 token 数差很多。要和某一家模型的窗口对齐，再改用那家的 tokenizer 重算块长，重叠仍按上面的比例和「一条事实的长度」来定，不要把 80 这个字符数直接当成 80 个 token。装进模型窗口是另一件事，按 `MAX_CONTEXT_CHARS` 从高相关往里装，超了丢掉后面的，不回头改切分。

## 本仓库怎么切

先拆成段落、表格、图片、脚注块，再按种类切。块首写标题路径；PDF 再加页码，形如 `[p.3 / 差旅 / 住宿限额]`。扫描件用识别框还原阅读顺序。平均每页不足 40 字就按页渲染。识别完仍然没有字，整份拒绝。打不开的 PDF 整份拒绝。Windows 中文 txt/md 先按 UTF-8，失败再按 GBK。超过 10MB 拒绝。

| 问题 | 现在 | 为什么停在这里 |
|---|---|---|
| 格式乱猜 | 只收 `.txt` `.md` `.pdf` | 猜格式会把二进制当文本切进去 |
| 标题切开后不知道属于哪一节 | 块首写标题路径和页码 | 解析器写路径，不另调模型 |
| 代码、表格从中间断开 | 围栏和表格整段保留；表太长按行切并重复表头 | 列名不能只出现在第一块 |
| 跨页表、多级表头、合并格 | 列数相同且无新表题就拼；空格先下再右补；多级表头竖着拼 | 启发式。真空和合并空分不开 |
| 表格检索对不上单元格 | 块里先写摘要（标题、列名、行数），再跟 Markdown 表 | 摘要用来召回，表体用来对数字。还没有行转条目 |
| 双栏、页眉页脚 | 中间有沟才分栏，先左后右；多页顶端底端重复的丢掉 | 沟不明显的双栏仍可能横着读 |
| 图、脚注 | 图片块留下近旁图注和页内位置；页底编号行当脚注 | 不做视觉模型 |
| 句子切在窗口边上 | 只有超长正文才 500 / 80 | 见上一节 |
| 切出来的块塞不进窗口 | 按相关度从高往低装，超了丢掉后面的 | 这是装上下文，不是改切分 |

Markdown 按标题、围栏、管道表拆块。PDF 有文本层时用 pdfplumber 抽词框和表，抽不到再退回按页纯文本。旧库要重新上传才会变成结构块。

这些留到以后再做：

| 问题 | 触发再做 | 倾向 |
|---|---|---|
| 版面启发式不够 | 双栏无沟、复杂版式、长乱码文本层开始砸人 | LlamaIndex 或版面模型 |
| Excel | 要收 `.xlsx` | 按上一节拆 sheet、填合并格、行转条目 |
| 行转条目 | 问的是某一格，命中的却是整张表 | 一行一条目，摘要另留一块 |
| 表格计算 | 用户要汇总，模型开始口算出错 | 检索仍找表，加减交给工具 |
| 父子块 | 小块能搜到，生成缺上下文 | 检索用小块，生成换上该块所在的节 |
| 按 token 切 | 要和某一家模型的窗口对齐 | 再上那家 tokenizer |
| 重叠块近重复 | 前几名经常是同一段的两个窗口 | 相邻高分块合并 |
| 文本层是长乱码 | 有字但全是错码，平均每页超过 40 字 | 现在不会改走识别 |

## 名词

### 请求怎么走

**Agent。** 模型自己决定下一步：调用工具，或者直接作答。固定写死「检索一次再生成」就只是一条流水线。

**工具调用。** 把检索描述成一个函数交给模型。模型返回函数名和参数，程序执行，把结果塞回对话，模型再决定继续搜还是作答。本仓库只有检索这一个工具。

**loop。** 模型外面的驱动：想、调工具、看结果、再想，直到写出答案。必须有步数上限。本仓库最后一轮禁止再调工具。相同问句不搜第二次。

**沙箱。** 一次工具调用允许碰到的范围。本仓库只放行检索，检索只读切片。不认识的工具返回一条结果。会执行命令的工具出现之前，不上进程沙箱。

**工作记忆。** 多轮里的「它」「再详细点」靠最近对话。对话和资料抢同一个窗口。本仓库由请求带上历史，最多占窗口三成，不写入知识库。

**会话隔离。** 历史跟着这次请求进来，一进函数就复制一份，请求结束就丢。图不挂检查点，避免所有请求写进同一条记忆。

**消歧。** 一种读法能补成唯一问句，就改写后去检索。几种读法会搜到不同文档，这一轮只反问一个缺口，先不检索。

**查询改写。** 把带指代、带省略的问句写成不看历史也能检索的一句。生成仍用用户原话。

**多查询 / HyDE。** 本仓库不做。多查询把几路切片抢进同一份上下文。HyDE 用假想答案的向量去检索，写偏会召回错型号、错错误码。

### 文档怎么进库

**解析。** 从文件里重建阅读顺序。字都在、表被拆平，后面的检索救不回来。

**Chunk。** 一块能单独被检索、也能单独放进窗口的文本。五种切法见上文。

**重叠。** 相邻两块故意重复一段。设置见上文。本仓库 500 字一块、重叠 80 字，下一块从 420 字后开始。重叠不去重。

**Embedding。** 把一段文字变成一串数。语义接近的文字，向量也接近。型号只差一个字母、错误码只差一位时，向量常常仍然很近。

**索引。** 本仓库把向量存在 PostgreSQL 的 JSONB 列里，查询时全表算余弦。上万再在这份 Postgres 上加 pgvector 的 HNSW。HNSW 上层稀、下层密，查询从上层贪心走到下层。每个点最多连 M 个邻居。每层保留的候选宽度叫 ef，越大越接近全表扫描。现在切片少，全表精确余弦，没有这层漏召回。

### 问题怎么找到证据

**混合检索。** 关键词一路、向量一路，各自取出一批再合成。词必须原样出现时靠关键词，用词对不上时靠向量。

**双编码器。** 问句和切片分开编码。切片的向量在入库时算好。它看的是两段各自的意思像不像，不是这两段放在一起能不能回答。

**BM25。** 问句里的词在某切片里出现、又不太常见，分就高。`N` 是参与打分的切片数，`n_t` 是含有词 `t` 的切片数，`tf` 是 `t` 在这条切片里出现的次数，`dl` 是这条切片的词数，`avgdl` 是平均词数。`k1 = 1.5`，`b = 0.75`。对数是自然对数。中文按连续两字切，英文和错误码整词。只留下分数大于 0 的切片。

`IDF(t) = ln( (N − n_t + 0.5) / (n_t + 0.5) + 1 )`

`贡献(t) = IDF(t) × (tf × (k1 + 1)) / (tf + k1 × (1 − b + b × dl / avgdl))`

**向量检索。** 相似度是余弦，越接近 1 越像。长度是 0 时记 0。入库向量不另做归一化。

`cos(q, d) = (q · d) / (|q| × |d|)`

**RRF。** 名次从 1 起。两路分数的量纲不同，不能直接相加。

`RRF(d) = Σ 1 / (60 + rank_i(d))`

两路都排第 1 时，`RRF = 1/61 + 1/61`。一路第 1、另一路没有时，`RRF = 1/61`。

**精排 / 交叉编码器。** 把问句和切片拼成一对再打分。只重排已经召回的一小批。不配模型就停在 RRF 的名次。分数只比较这一批候选，不是答对的概率。

**MMR。** `MMR(d) = λ × Sim(d, q) − (1 − λ) × max Sim(d, 已选)`。λ 靠近 1 就只看相关。本仓库不算这式，同一文档有条数上限，超了先跳过，条数不够再按原序补回。

**硬约束 / 预过滤。** 型号、错误码在 BM25 和余弦之前按原文收窄。问句同时提到两个错误码、滤完没有切片时，退回原集合。先取出前 K 再过滤，这 K 条可能一条都不符合条件。权限过滤还没有，也要放在参与排序之前。

**上下文组装。** 按相关度从高到低装进窗口，装到 `MAX_CONTEXT_CHARS` 为止。对话另占预算。窗口一长，模型更用得上开头和结尾，所以最相关的放在最前。

### 答案怎么被拦住

**无证据不输出。** 这一轮没有任何检索切片，就不把模型正文发给用户，只回复不知道。看的是「有没有切片」，不看每一句能不能从切片推出来。消歧反问可以不检索。

**引用校验。** 本仓库没有。返回的来源只是文档名。三档越往下越严：答案里的编号是否指向某条切片；专名、数字、日期是否出现在原文；另一个模型判断切片能否推出这句话。只做第一档时，模型可以标一个相关切片，句子本身仍然是编的。

**证据充分性。** 排在前面的几条合在一起仍可能答不全。充分性问「够不够回答」。引用校验问「已经写出的这句有没有依据」。

### 准不准怎么算

每个数只解释一个阶段。先有标注：哪些切片是正确证据，回答必须覆盖哪些事实。多题先按题算，再取平均。召回的 K、精排前的 K、交给模型的 K 不是同一个数。本仓库还没有标注集，下面这些数现在算不出来。组怎么摆见下一节。

下面用同一道题当底：正确切片 4 条，前 5 条里命中 2 条，第一条正确切片排在第 2 名。

**Recall@K** = `|前 K 条 ∩ Rel| / |Rel|`。上例 `2/4 = 0.5`。评测用 `Recall@20` 看精排之前的候选。这里是 0，后面的精排没有机会。

**Precision@K** = `|前 K 条 ∩ Rel| / K`。上例 `2/5 = 0.4`。精确低时，窗口会被无关切片占满。

**F1@K** = `2 × Precision@K × Recall@K / (Precision@K + Recall@K)`。上例 `4/9`。

**Hit@K。** 前 K 条里有一条正确就是 1。上例是 1，尽管四条只回来两条。

**MRR@K。** 第一条正确切片排第 `r` 名，这一题得 `1/r`。前 K 里没有，得 0。再对题平均。上例这一题贡献 `1/2`。评测用 `MRR@5`。

**nDCG@K。** 相关记 1，不相关记 0。`DCG@K = Σ rel_i / log2(i + 1)`，`i` 从 1 到 K。再除以理想排序的 IDCG，满分是 1。第 1 名和第 3 名相关时，`DCG@5 = 1.5`。两条都排到最前时 `IDCG ≈ 1.631`，`nDCG@5 ≈ 0.92`。评测用 `nDCG@5`。

**MAP。** 每道题在命中正确切片的那些名次上把当时的精确率平均，再对题平均。评测不报它，用 `Recall@20`、`nDCG@5`、`MRR@5` 分开看。

**Evidence Recall@K** = `|前 K 条盖住的事实| / |必须覆盖的事实|`。分母是事实条数，不是切片数。评测用 `@6`，因为最终交给模型的是这几条。`Recall@K` 高而这个数低：正确切片进来了，合在一起仍答不全，或同一文档的相邻切片占满了名额。

**答案正确率** = 答对的题数 / 题数。这个数下降时，先看 Evidence Recall。低就是没给到证据，高就是给到了仍写错。

**P95。** 耗时从小到大排，取第 `⌈0.95 × N⌉` 次。精排增加的时间和生成的时间分开记。

**RAGAS。** 本仓库不跑。忠实度是被上下文支持的断言比例。答案相关度是从答案反问出的题和原问的余弦平均。上下文精确率看有用的块排得靠不靠前。上下文召回看标准答案的句子有多少能在检索结果里找到依据。

放在一起看：`Recall` 高、`nDCG` 低，证据进了候选，没有排上来。`nDCG` 高、Evidence Recall 低，最像的几条在前面，事实仍不齐。Evidence Recall 高、答案正确率低，问题在生成。

### 和别的路线比

**朴素 RAG** 检索一次就生成。本仓库的 loop 可以再搜，没有切片就不把模型正文给用户。

**微调** 适合改语气和输出格式。知识会改、回答要指回原文，用 RAG。本仓库只做 RAG。

**长上下文** 更贵，中间的证据仍然容易被忽略。本仓库仍按预算从高相关往里装。

**多跳。** loop 可以换一个问句再搜，有步数上限。没有事先把用户问题拆成一组子问题。

**GraphRAG** 先建实体图。问的是某个型号、某个错误码怎么处理时，图多绕一圈。本仓库没有实体图，证据是切片。

## 评测

要证明精排有用，就固定知识库、题目、切片、向量模型和生成模型，只改排序。

| 组 | 配置 | 这一组在回答什么 |
|---|---|---|
| A | 只做向量检索 | 没有关键词、没有精排时，正确证据在哪 |
| B | 关键词 + 向量，RRF 融合 | 混合召回本身带进了多少 |
| C | B 之后用 BGE-Reranker-v2-m3 | 加上基线精排，比 B 多对了多少 |
| D | B 之后用 Qwen3-Reranker-0.6B | 换一个精排模型，比 C 多对了多少、慢了多少 |

C 比 B 好，才能说精排有收益。A 到 B 的差距算在混合召回头上。精排前取 30 条还是 60 条，要单列，比的是覆盖、P95 和费用。

| 指标 | 看的阶段 | 怎么读 |
|---|---|---|
| Recall@20 | 精排之前的候选 | 这里是 0，后面的精排没有机会 |
| nDCG@5 | 排序靠不靠前 | 排到第 6 名以后，这次的前 5 里就没有它 |
| MRR@5 | 第一条正确切片的名次 | 第 1 名得 1，第 2 名得 1/2，前 5 名之外得 0 |
| Evidence Recall@6 | 最终交给模型的证据 | 必须覆盖的事实里，前 6 条盖住了多少 |
| 答案正确率 | 生成 | 下降时先分清是没给到证据，还是给到了仍写错 |
| P95 延迟 | 精排这一跳 | 和生成的时间分开记 |

事实按人能核对的短句写，例如「先断电」「型号是 A 型」「错误码是 E07」。困难题单独出数：型号只差一个字、错误码只差一位、版本不同、表格里参数接近。几十道这类题比几百道 FAQ 更能决定精排留不留。

一次答错，用正确切片的 id 对名次：关键词名次和向量名次都空，是召回没捞到。融合名次在精排窗口内、最终名次空，是精排把它压下去了，或同一来源封顶时被挤掉。最终名次很靠前、答案仍错，是证据到了生成，生成没用上，或这几条本来就缺事实。

本仓库还没有标注集，也没有把四组自动跑完的程序。精排默认关闭。打开追踪之后，日志里有各阶段名次，可以手工对一次答错。
