## 一句话

Claude Code 用摘要腾窗口，用 ripgrep 找代码。Cursor 把代码切片后做向量索引，另外用 Tab 预测下一步编辑，用投机解码把改动写进文件。Aider 用符号图挤进窗口。龙虾（LobeChat）早期把会话放在浏览器本地库，服务端库是后来为了多端和知识库加上的。

## 1. Claude Code 怎么做上下文压缩？

窗口里是系统提示、对话、每次工具调用和读过的文件。内容一多，注意力被冲淡，这叫 context rot。窗口还有硬上限，顶满会话就断。

压缩叫 compaction。再调一次模型，让它把到目前为止的对话写成结构化摘要，用这份摘要换掉原来的长历史，然后在新窗口里接着做。有损。可以带重点，例如 `/compact` 时写明留下认证改造、丢掉测试调试。快满时自动做同一件事，阈值可以用 `/autocompact` 调，例如 `500k`，或 `auto` 回到该模型的默认窗口。

压缩完这些还在，因为它们是重新读进来的，不是从摘要里抢救的：

| 内容 | 压缩之后 |
|---|---|
| 系统提示、输出风格 | 继续生效 |
| 项目根的 CLAUDE.md、不带路径条件的规则、自动记忆 | 从磁盘再注入 |
| 技能清单 | 按当前技能重建 |
| 计划模式里写下的计划 | 从磁盘再注入 |
| 本会话读过或改过的文件 | 最多重读 5 个，优先最近改过的。单文件超过约 5000 token 只留路径 |
| 已经调用过的技能正文 | 再注入，单份约 5000 token、合计约 25000 token，超了先丢最旧的 |
| 带子目录路径条件的规则、嵌套 CLAUDE.md | 跟对话一起被摘要吃掉。要跨压缩保留，就放到项目根 |
| 钩子早先塞进对话的内容 | 跟对话一起被摘要 |

自动压缩容易压坏：触发时上下文已经很长，模型最不灵，又猜不到你下一句要做什么。长调试之后突然去改另一个告警，摘要里往往没有那个告警。所以换任务前自己压，并写明要留下什么。

另外三招不要和压缩混成一件事：

| 情况 | 做法 | 留下什么 |
|---|---|---|
| 还是这件事，窗口里的内容都还用得上 | 继续说 | 原历史 |
| 走错了一条路 | `/rewind`，退到还没走错的那条消息 | 有用的文件读取还在，失败尝试丢掉 |
| 同一件事，但调试和搜索把窗口撑满了 | `/compact`，可带重点 | 模型写的摘要，加上表里那些重新读入的材料 |
| 换一件不相干的事 | `/clear` | 你自己写的简报。没有自动摘要 |
| 下一步会吐出大量中间结果，只要结论 | 子代理 | 搜索和阅读留在子窗口，父窗口只收回摘要 |

子代理是提前少占窗口：搜索、核对、写文档放进一个干净的上下文，父会话只拿结论。压缩是事后把已经堆进来的历史变短。

## 2. Claude Code 怎么检索代码？

不给仓库做向量索引。模型像人翻代码一样当场搜，Anthropic 把这个叫做 agentic search。

三步，按花掉的上下文从少到多：

1. Glob：按路径模式列文件，返回的是路径。
2. Grep：ripgrep，按符号、字符串、正则找行。命中的是文件里的原文，带得上位置，模型可以再读那一页核对。
3. Read：把选中的文件读进上下文。这一步才贵。

代码题多数是「这个函数、这个字符串、这个 import 在哪」。精确匹配对得上，读到的是完整文件，没有切片把函数切成两半，也没有「索引还没跟上刚才的保存」。向量索引要事先建、随每次编辑更新，换 worktree 还要多份。

搜索会刷屏。宽范围的探索交给子代理，自己的窗口里只留它交回来的文件和结论。判断标准：这段工具输出以后还要不要再看。只要结论，就不要留在父窗口。

向量索引仍然适合另一种问法：想找的是行为，代码里的词和问题对不上，仓库又大、又要反复问。那是编辑器助手（先建索引再取几段）的路。2026 年一份仓库问答对照里，语义检索答对更多、也更便宜；子代理搜索的失败很多出在「派出去的人交回一份很顺、但是错的结论」。两条都要会讲。面试时先讲 Claude Code 为什么用精确搜索，再补这一句代价。

## 3. 龙虾之前是什么设计？

龙虾是 LobeChat。早期默认没有你的服务器：会话、助手配置在浏览器的 IndexedDB 里，密钥留在本地，请求从浏览器直接打到模型服务商。换一台电脑，记录不在。文件和知识库也不在，因为没有地方放大文件，也没有向量库。

插件走 function calling。工具描述交给模型，调用发生在用户这端。没有一台服务器替用户保管密钥、代跑工具。

后来的服务端库没有重写界面状态。同一层 store，底下换成另一条路：浏览器走本地库，服务端走 tRPC 到 Postgres。知识库要 pgvector。图片和上传文件不塞进数据库行里，走 S3，库里只留地址。用户存进来的 API Key 在库里加密。身份要单独接，官方云用 Clerk，自建常用 NextAuth。

客户端库当时就按关系表来建，所以接到 Postgres 时业务层几乎能复用。这是这题要讲的设计，不是「后来又用 Vite 拆了前端」。

再往后客户端换过 PGlite，也就是浏览器里的 Postgres，本地也能做向量检索。那是下一阶段。面试问「之前」，答 IndexedDB、直连模型、没有知识库。

## 4. Cursor 怎么做代码索引？

打开仓库就开始索引。文件按语法切块，块做成向量，放到服务端的向量库。问代码时先按语义取出相关块，再让模型读原文。

增量靠 Merkle tree：每个文件一个内容哈希，目录哈希由子节点哈希算出。改一个文件，只影响这个文件和它的父目录直到根。哈希没变的整枝跳过，不用把五万个文件名再传一遍。块的向量按块内容缓存，没改的块不重新嵌入。嵌入是贵的那一步，所以放在后台做。

索引里是相似度，没有「谁调用了这个函数」。改签名会不会弄坏别处，向量回答不了。源码在做嵌入时经过服务端，做完不把原文存下来。团队里另一份几乎一样的仓库，可以用相似度哈希复用已有索引，搜索时再用客户端自己的哈希过滤，避免看到自己磁盘上没有的文件。

和 Claude Code 并列着记：一个事先嵌入、问的时候取块；一个不建索引、问的时候用 ripgrep。符号对得上用后者，用词对不上用前者。

## 5. Aider 的 repo map 为什么不用向量？

Aider 比 Claude Code 更早把整个仓库塞进窗口。tree-sitter 抽出定义和引用，文件是点，引用是边，用 PageRank 挑被引用最多的符号。窗口里放的是这些符号的签名和关键行，不是整文件，也不是向量召回的碎块。预算默认大约 1000 token，用 `--map-tokens` 调。当前对话涉及的文件会排得更靠前。

它解决的是「写这里要知道别处已经有什么函数」。调用关系在图上，不靠两段代码长得像。代价是地图是给这一轮提示词用的摘要，不是一个可以再问「谁调用了它」的活图。仓库特别大时，排不进预算的符号模型看不见。

三套代码上下文可以放在一张表里：

| | 事先建什么 | 窗口里放什么 | 问「这个符号在哪」 | 问「有没有类似实现」 |
|---|---|---|---|---|
| Claude Code | 不建 | 搜到的原文 | 合适 | 靠模型多搜几次 |
| Cursor | 语法块的向量 | 召回的块 | 名字差很多时会偏 | 合适 |
| Aider | 符号引用图 | 排进预算的签名 | 被引用多的看得到 | 图上没有这条边 |

## 6. 还常被拿来对照的两题

MemGPT 把窗口当内存，把外存当磁盘。快满时由模型自己决定把哪段写出去、下次把哪段换回来。Claude Code 的压缩是运行时的固定策略：快满了就摘要。MemGPT 是模型多了两个记忆工具。面试要分开：一个是产品替你压，一个是模型自己调度。

Contextual retrieval 管的是切片丢了章节。入库前让模型给每个切片写一句它属于哪份文档、哪一节，拼在切片前面再做嵌入，同时保留关键词检索。和「切的时候把标题路径写进块首」是同一件事，只是标题由模型写，不由解析器写。本仓库两条都还没有。

## 7. Cursor 除了索引还有什么？

三件。都是「大模型慢、而且会打扰正在写代码的人」，所以把活拆开。

Tab 预测的是下一步动作，不只是光标处补全。每次击键或移动光标都问一次：这段附近要怎么改，改完下一处在哪个文件。把握不够就不显示。上下文是当前任务、最近的修改、相关文件和诊断。建议被接受还是被按掉，拿来做在线强化学习。公开的下一代模型建议少了 21%，接受率高了 28%。请求量大约每天四亿次，所以延迟和「少打扰」比多补几行重要。

Fast apply 把一次修改拆成两段。强模型在对话里决定改什么，往往只给出一段草图。写进文件交给专门的 apply 模型，任务是对照当前文件把整份文件重写出来。他们不用 diff：diff 比整文件少见，模型用来想的 token 更少，行号还经常被分词器粘成一个 token，第一下就得赌对行号。速度靠 speculative edits：草稿就是原文件本身，没改的整段直接接受，只在真正改动的地方重新生成。公开数字是 70B 上大约每秒 1000 token，相对不做投机的 Llama-3-70B 大约 13 倍。

Shadow workspace 让模型在改动落到用户文件之前看到语言服务的诊断。复制一份内存里的文件不够：那份副本会进同一个 language server，跳转结果里出现副本，Go 这类语言还会报重复声明。所以另开一个隐藏的编辑器窗口，改动在那边应用，诊断送回来。窗口之间不能直接通信，就借扩展宿主转一跳。多个任务排队用同一扇隐藏窗口，因为模型可以停住等，人不能。内存大约再占一份，所以当时是自己打开的，空闲一会儿就关掉。语言服务能看诊断；真正把程序跑起来是下一步，隐藏窗口还没解决。

## 和本仓库的差距

本仓库的窗口靠滑动：最近几轮对话最多占窗口三成，资料按相关度装到 `MAX_CONTEXT_CHARS` 为止。没有「再调一次模型写摘要、换掉历史」这一步。多轮变长时，旧的检索过程不会被总结，只是被预算裁掉。

检索的对象是上传文档的切片，不是代码库。问句做 embedding，和切片算余弦。没有 Glob / ripgrep，没有符号图，也没有把搜索丢给子代理。文档问答要的是语义近邻；代码定位要的是符号原文。两套不要互相套。

会话存在服务端这次请求的 `history` 里，不在浏览器本地库，也没有第二套 Postgres。上传文件进 SQLite，没有对象存储。知识库还小，所以没有龙虾服务端那三件：登录、pgvector、S3。
