# 项目选型面试题

对着本仓库答。选型表见 [architecture.md](architecture.md)。后面只往这里加题，不要另开文件。

## 1. 为什么流式用 SSE，不用 WebSocket？

**先说结论：** 本项目是一次提问、服务端单向推 token，答完即断。SSE 是 HTTP 上的单向流；WebSocket 是双工长连接。现在没有「同一条连接上客户端还要再发东西」，上 WS 是多余的连接管理。

**和本仓库对得上的点：**

- 客户端只在开头 POST 一个 `question`，之后只收 `sources` → `delta` → `done`。没有 HITL 批准、没有连接上续问、没有服务端再等客户端。
- 上游也是 OpenAI `stream=True`（HTTP 一块块吐），不是 WS。中间再开一条 WS，两边协议还要对一遍。
- `/ingest`、`/ask` 已经是 FastAPI HTTP。`/ask/stream` 用 `StreamingResponse` 还在这条栈上：缺 key 仍能在写头前 503，curl `-N` 能打，不必自己做心跳、房间、断线重连。
- 浏览器原生 `EventSource` 只能 GET，所以本仓库是 **POST + SSE + fetch**，不是改成 GET，更不是因此改 WS。不能 POST 不是 WS 的理由。

**什么时候该换成 WebSocket：** LangGraph 真上了 HITL（同一条连接上人要回灌批准 / 改问题），或要在生成中途推结构化指令（而不只是 Abort 整次请求）。现在后置里才有 HITL，没到。

**追问：那取消生成呢？** `fetch` 的 `AbortController` 断 HTTP 就行，`stream_ask` 的 `finally: stream.close()` 会关掉上游。不为了 cancel 上 WS。
