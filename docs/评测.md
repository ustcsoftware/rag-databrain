# Agent 评测

活文档。后面加题写在本文。选型见 [architecture.md](architecture.md)，检索为什么要精排见 [选型面试题.md](选型面试题.md)，名词见 [技术名词.md](技术名词.md)。

## 一句话

要证明精排有用，就固定知识库、题目、切片、向量模型和生成模型，只改排序。四组放在一起比：正确证据进没进候选、排得靠不靠前、交给模型的几条盖住了多少事实、答案对不对、慢了多少、贵了多少。

## 1. 如何证明 Rerank 确实改善了效果？

回答写得顺，不能说明精排改善了效果。向量检索已经会把语义接近的切片送进来，模型可以用错证据写出很完整的步骤。换一个精排模型再看几条演示，分不清是题目变简单了、切片变了，还是排序真的变好了。

证明要三件一起做：消融、指标、成本。少一件就会把别的改动算到精排头上，或者只看到变准、没看到慢了多少。

### 消融：只改排序

四组共用同一份库、同一批题、同一种切片、同一个向量模型、同一个生成模型。组与组之间只改召回和排序。

| 组 | 配置 | 这一组在回答什么 |
|---|---|---|
| A | 只做向量检索 | 没有关键词、没有精排时，正确证据在哪 |
| B | 关键词 + 向量，RRF 融合 | 混合召回本身带进了多少，还没精排 |
| C | B 之后用 BGE-Reranker-v2-m3 | 加上基线精排，比 B 多对了多少 |
| D | B 之后用 Qwen3-Reranker-0.6B | 换一个精排模型，比 C 多对了多少、慢了多少 |

C 比 B 好，才能说精排有收益。D 比 C 好，才能说换模型值得。A 到 B 的差距算在混合召回头上，不要算成某个 Reranker 的功劳。

精排的输入条数也要单列实验。例如都从融合结果里取最终 6 条，一组精排前 30 条，一组精排前 60 条。比的是正确证据的覆盖、P95 和费用。候选越多，通常越慢、越贵；覆盖不上来，加候选就没有意义。

### 指标：每个数只解释一个阶段

每道题先标好：哪些切片是正确证据，回答必须覆盖哪些事实，怎样算答对。事实按人能核对的短句写，例如「先断电」「型号是 A 型」「错误码是 E07」。

| 指标 | 看的阶段 | 怎么读 |
|---|---|---|
| Recall@20 | 精排之前的候选 | 正确切片有没有进入前 20。这里是 0，后面的精排没有机会 |
| nDCG@5 | 排序靠不靠前 | 正确切片越靠前分越高。排到第 6 名以后，这次的前 5 里就没有它 |
| MRR@5 | 第一条正确切片的名次 | 出现在第 1 名得 1，第 2 名得 1/2，前 5 名之外得 0 |
| Evidence Recall@6 | 最终交给模型的证据 | 必须覆盖的事实里，前 6 条盖住了多少。一条切片可以盖住多件事实 |
| 答案正确率 | 生成 | 证据齐了仍可能写错。这个数下降时，先分清是没给到证据，还是给到了仍写错 |
| P95 延迟 | 精排这一跳 | 同一批请求里，比 95% 的请求都慢的那一次耗时。精排增加的时间和生成的时间分开记 |

Recall@20 高、nDCG@5 低：证据进了候选，精排没有把它抬上来。nDCG@5 高、Evidence Recall@6 低：最像的几条排到了前面，合在一起仍答不全，或者同一文档的相邻切片占满了名额。Evidence Recall@6 高、答案正确率低：问题在生成，不在精排。

精排分数只用来给这一批候选排序。没有标定之前，一个更高的分数不能当成「这句答对的概率」。

### 成本：和收益放在同一张表

费用按一次提问记。精排的花费大致随候选条数和模型大小增加。最终交给模型的条数不变时，生成的 token 差不多，多出来的主要是精排自己的时间和算力。

| 配置 | Evidence Recall@6 | 答案正确率 | 精排 P95 | 一次提问的精排代价 |
|---|---|---|---|---|
| B，不精排 |  |  |  | 无精排 |
| C，精排 30 条，留下 6 条 |  |  |  |  |
| C，精排 60 条，留下 6 条 |  |  |  |  |
| D，精排 30 条，留下 6 条 |  |  |  |  |

30 条已经盖住必要事实时，60 条只增加延迟和费用。正确率上升、P95 超出产品能等的时间，就要写明换的是哪一个：少候选、换小模型，或只对困难题精排。

### 困难题比普通 FAQ 更能看出来

普通问法上，只做向量检索往往已经能碰到答案，精排的差值会被平均掉。标注集里单独放一批容易排错的题，并按类出数，不要只报一个总平均：

- 型号只差一个字，例如 A 型和 B 型
- 错误码只差一位，例如 E07 和 E08、E07 和 E075
- 版本不同，正文几乎一样
- 表格里参数接近，行和列容易抄错

同一道题在 A、B、C、D 上各跑一次。题量不必大，几十道这类题比几百道泛泛的 FAQ 更能决定精排留不留。

### 一次答错，查它死在哪一列

每条候选留下这些名次：切片 id、关键词名次、向量名次、融合名次、精排分数、最终名次。用户指出一次答错时，用正确切片的 id 去对：

| 看到的情况 | 结论 |
|---|---|
| 关键词名次和向量名次都空 | 召回没捞到，换精排模型没用 |
| 融合名次在精排窗口内，最终名次空 | 精排把它压下去了，或同一来源封顶时被挤掉 |
| 最终名次很靠前，答案仍错 | 证据到了生成，生成没用上，或这几条本来就缺事实 |

### 本仓库

还没有这套标注集，也没有把四组自动跑完的评测程序。精排默认关闭，配上模型名才做交叉编码。打开追踪之后，日志里有上面那几列名次，可以手工对一次答错死在召回、融合还是精排。库、切片、向量模型和生成模型目前各只有一套，和消融要求的「只改变排序」是对齐的；缺的是题和标注。
